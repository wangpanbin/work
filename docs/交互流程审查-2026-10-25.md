## 结论先行

整站流程骨架是站得住的：**登录 → 浏览 → 影片详情 → 选座 → 支付 → 订单列表** 这条主链路的
状态划分（订单 5 态、座位 5 态）、错误码分流、WS 实时同步与权威重拉，都做过了实测与回归，
明显高于一般课程/毕设项目的完成度。2026-10-24 那一轮给 `MovieDetail` / `SeatSelect` /
`Payment` 补的「加载失败 + 重试」是实打实的改进。

但**那一轮改动漏了几处**，且补的只是「首拉失败」这一种异常：

1. **一条能造成资损的路径没有被任何测试覆盖**：选座页在同路由换场次时不重新加载，用户可能在
   错误的场次上锁座付款。`test/e2e/RESULTS.md` 的 22 个场景里没有这一条。
2. **「错误」与「空」仍然混为一谈**：订单列表、管理端三张表都还是「拉取失败 → 页面显示
   ‘暂无订单记录’ / ‘暂无数据’」。
3. **同一个后端副作用，两条路径一个披露一个不披露**：聊天下单会告诉你「这会取消你现有的待支付单」，
   选座下单不会。

最该先修的是下面 P0 的两条 —— 它们都不是样式问题，是「用户付了钱但拿错票」和「订单凭空消失」。

## P0 · 阻塞级（会买错场次 / 丢订单）

### P0-1 选座页在同路由换场次时不重新加载 —— 可能锁错场次

**证据**

- `cinema-web/src/views/SeatSelect.vue:29` —— `sessionId` 是 `computed(() => String(route.params.sessionId))`，是响应式的。
- `cinema-web/src/views/SeatSelect.vue:261-281` —— 座位图**只在 `onMounted` 里拉一次**。
  全文没有 `watch(() => route.params.sessionId, ...)`，也没有 `onBeforeRouteUpdate`。
- Vue Router 4 的既有行为：同一路由记录只换 params 时**复用组件实例**，`onMounted` 不再触发。
  源码级证据（本机 `vue-router` 4.x 的 dist 源码，未入库，故只描述不引路径）：`RouterView` 的渲染
  函数是 `h(ViewComponent, assign({}, routeProps, attrs, {...}))`，**组件上没有 `key`**；
  `ViewComponent` 取自 `matchedRoute.components.default`，同路由记录下是同一个组件对象 →
  Vue 的 patch 算法原地复用实例。同时 vue-router 内部把这类记录称为 `updatingRecords`
  （「记录未变、只有参数变了」），并专门提供 `onBeforeRouteUpdate` 守卫兜底 ——
  这本身就说明它**不会**重新挂载组件。

**触发路径（当前就存在，不是假想）**

选座页 → 打开聊天浮窗（`cinema-web/src/composables/useChatContext.ts:12-14` 只隐藏 `/payment` 与
`/admin`，`/seat` 下浮窗照常可用）→ 助手给出**另一个场次**的座位建议卡 → 点卡片 →
`router.push({ name: 'seat-select', params: { sessionId: B } })`
（`cinema-web/src/components/chat/actionCardRoute.ts:17-28`）。

结果：**URL 变成 `/seat/B`，页面仍是 A 场的座位图，WS 仍连着 A，preselect 也没有生效**
（`SeatSelect.vue:274-277` 的 preselect 同样只在 `onMounted` 里读）。

**后果**

用户在 A 场的图上选座、点「确认锁座」→ `SeatSelect.vue:337` 发出的请求是
`lockSeats({ sessionId: B, seatIndexes: A 的座位索引 })` → **锁的是 B 场的座位，钱按 B 场付**。
若 A、B 是同一部影片的不同场次（最常见的推荐场景），界面几乎看不出差别。

**建议**

在 `SeatSelect.vue` 里把「装载一个场次」抽成一个函数（关旧 WS → 重置 seat store → 重拉位图 →
应用 preselect），然后 `watch(() => route.params.sessionId, reinit)`，或用 `onBeforeRouteUpdate`。
`cinema-web/src/views/MovieDetail.vue:21` 有同类隐患（`movieId` 是 setup 期快照而非响应式），
只是当前没有 `/movie/A → /movie/B` 的活路径，建议一并改掉。

### P0-2 同场次重复锁座：旧单被静默取消，新单失败则两头落空

**证据**

- `cinema-server/src/main/java/com/cinema/modules/order/service/OrderLockService.java:88-93`
  —— 锁座前先 `closePending(pending)` **取消同场次的旧待支付单**。
- 同文件 `:96-100` —— 取消旧单**之后**才去锁新座位；新锁冲突则抛「座位已被占用」。
- `cinema-server/src/main/java/com/cinema/modules/seat/vo/SeatMapVO.java:16-34`
  —— 座位图接口**不返回待支付单号**，前端无从知道「这个场次我已经有一笔待支付单」。

**后果**

用户在同场次重新锁座：旧单已被取消 → 若新座位被抢 → 新锁失败 → **用户手上既没有旧单也没有新单**，
座位被释放，回订单列表只看到一笔「已取消」且没有任何解释。

**同一后端副作用，聊天那条路径是披露了的**：
`cinema-web/src/components/chat/OrderProposalCard.vue:164-166` 会显示「将取消你的待支付单」。
选座这条路径一个字都不说。

**建议**

`SeatMapVO` 补 `pendingOrderNo` / `pendingExpireAt`（后端已有 `PendingOrderQuery#find` 可复用，
见 `OrderLockService.java:211-213`），选座页在有存量待支付单时出一次确认弹窗。
再考虑把后端的顺序改成「先锁新座位、成功后才关旧单」，避免失败路径两头落空。

## P1 · 高（用户会走错路，或拿不到本该有的反馈）

### P1-1 支付页超时按钮的文案与实际行为不一致

`cinema-web/src/views/Payment.vue:330-331` —— 按钮文案是「已超时,重新选座」，但点击执行的是
`redirectToOrders()`：3 秒后跳**订单列表**（`Payment.vue:94-99`）。按钮说「重新选座」，做的是「跳订单页」。

更糟的是 `autoRedirected` 已置位时 `redirectToOrders()` 直接 return（`Payment.vue:95`），
所以**超时后那 3 秒窗口内点按钮完全没有反应**，用户以为按钮坏了。

**建议**：超时时把按钮真的接到 `goSeat()`；或者拆成两个按钮（「重新选座」/「去订单列表」）。

### P1-2 订单列表把「请求失败」显示成「暂无订单记录」

`cinema-web/src/views/OrderList.vue:49-62` —— `load()` **没有 catch**，失败后 `orders` 保持 `[]`；
`:178` 于是渲染 `el-empty`「暂无订单记录」。用户本来有 20 单，网络抖一下页面就变成
「你一单都没有」，而错误 toast 一闪而过就没了。

对比：`MovieDetail` / `SeatSelect` / `Payment` 都在 2026-10-24 那轮补了「错误态 + 重试」，
**订单列表漏改**。

**建议**：照抄 `SeatSelect.vue:381-386` 的 `.load-error` + 重试按钮写法（样式已抽到
`main.css` 的共享类，五个视图共用同一份）。

### P1-3 管理端 Dashboard 请求失败即整页空白

`cinema-web/src/views/admin/Dashboard.vue:88-95` —— `load()` 无 catch，`data` 保持 null；
`:145` 的 `<template v-if="data">` 把整块内容挡掉 → 管理员只看到一个页头，**无错误、无重试**。
`onMounted(load)`（`:130`）同时产生一条未处理的 Promise rejection。

`AdminHome.vue` 与 `LiveDashboard.vue` 的同类问题已在 2026-10-24 修过，**唯独 Dashboard 漏改**。

### P1-4 点击「我已锁」的座位没有任何反馈

`cinema-web/src/components/SeatItem.vue:100-117` —— `seatStore.toggle()` 对 `LOCKED_MINE`
直接返回 false（`cinema-web/src/stores/seat.ts:126` 只放行 `AVAILABLE` / `SELECTED`），
而 `unavailable` 只包含 `SOLD` / `LOCKED_OTHER`（`SeatItem.vue:83`），
`selected.size >= maxSelect` 也不成立 → **两个提示分支一个都不进**。

用户看到一片绿色（我已锁）的座位，点下去毫无反应 —— 既没有提示，座位也不变。
同一文件里 `SOLD` / `LOCKED_OTHER` 都有提示，唯独 `LOCKED_MINE` 漏了。

**建议**：`LOCKED_MINE` 分支给一句「这是你已锁定的座位」（引导去支付，而不是让它看起来能点）。

### P1-5 三个管理端 CRUD 页的保存 / 删除按钮没有 loading 与 disabled

`cinema-web/src/views/admin/MovieManage.vue:135`、`HallManage.vue:115`、`SessionManage.vue:220`
—— `onSubmit` 没有并发闸门，按钮也不 disabled → **连点两下就 POST 两次，建出两条影片/影厅/场次**
（这几个后端端点没有幂等键）。

删除同理：`MovieManage.vue:105-107`、`HallManage.vue:95-97`、`SessionManage.vue:172-175`。

**建议**：加 `submitting` ref，按钮 `:loading="submitting" :disabled="submitting"`。

## P2 · 中（说得过去，但会磨掉用户耐心或造成误解）

### P2-1 管理端编辑影厅会静默清空 VIP 行

`cinema-web/src/views/admin/HallManage.vue:30-34` —— `openEdit` 把 `vipFromRow` 置为 `undefined`
（前端 `Hall` 类型 `cinema-web/src/types/admin-types.ts:3-10` **根本没有这个字段**）；
`:37-39` 提交前把它从 payload 删掉；
后端 `cinema-server/src/main/java/com/cinema/modules/admin/controller/AdminHallController.java:120-124`
删光全部座位后按 `vipFromRow = null` 重插 → **整厅 VIP 座位变回普通座位**，
而界面提示只说了「重建座位布局」，没提会丢 VIP。

**建议**：`Hall` 类型补 `vipFromRow`，编辑时回填并原样提交。

### P2-2 管理端三张表把「请求失败」显示成「暂无数据」

`MovieManage.vue:23-25`、`HallManage.vue:17-19`、`SessionManage.vue:37-39` —— catch 全空，
表格显示 Element Plus 默认的「暂无数据」，**没有错误态，也没有重试入口**。与 P1-2 同源。

### P2-3 管理端影片列表硬编码前 20 条且没有分页

`cinema-web/src/views/admin/MovieManage.vue:21` —— 固定 `page: 1, size: 20`，`PageData.total`
没用，模板也没有 `el-pagination` → **第 21 条及以后的影片在管理端永远看不到**。
`SessionManage.vue:25-28,42-51` 已经接好分页，MovieManage 漏了。

### P2-4 LiveDashboard 每 5 秒轮询，后端一挂就是 toast 风暴

`cinema-web/src/views/admin/LiveDashboard.vue:99` —— `setInterval(loadSummary, 5000)`；
`cinema-web/src/api/admin.ts:26-28` 走共享 `request` 实例 → 每次失败都由
`cinema-web/src/api/request.ts:81-83` 弹一次 `ElMessage.error`。
2026-10-24 修的是页面内横幅（`LiveDashboard.vue:125-131`），**拦截器那条 toast 仍每 5 秒重复**。

**建议**：该请求传 `{ skipErrorToast: true }`，由页面自己提示（本仓 `request.ts:12-16` 的既定规则）。

### P2-5 登录失败会弹两次提示

`cinema-web/src/api/user.ts:4-6` —— 登录请求没传 `skipErrorToast` → 拦截器先弹一次，
`cinema-web/src/views/Login.vue:82-89` 再弹一个 `ElMessageBox` → 用户看到 toast + 弹窗两层。
这违反本仓自己的规则（`request.ts:12-16`：自己弹提示的请求必须声明 `skipErrorToast: true`）。

### P2-6 登录表单校验失败会产生未处理 Promise rejection

`cinema-web/src/views/Login.vue:70` —— `await loginFormRef.value?.validate()` 写在 try/catch 之外，
而 Element Plus 的 `validate()` 在校验失败时是 **reject**。
同文件 `handleRegister` 的同一处已被 P3-3 修过（`Login.vue:113-117`），**`handleLogin` 漏改**。

### P2-7 影片详情页切日期时，「场次加载失败」的提示不会被清掉

`cinema-web/src/views/MovieDetail.vue:74-84` —— 命中缓存的分支**提前 return，没把 `sessionsError` 置 null**。
于是：某天拉取失败 → 切到有缓存的日期 → **错误提示仍在**，而且因为 `:212-216` 的错误块与
`:218` 的场次列表不是互斥关系，**上一个日期的旧场次会继续显示在下边**。

### P2-8 管理端表单的必填提示是英文默认文案

`cinema-web/src/views/admin/MovieManage.vue:113-121` 用的是 `required` 属性。
Element Plus 2.14.5 确实会据此合成 `{ required }` 规则
（`element-plus/es/components/form/src/form-item.vue_vue_type_script_setup_true_lang.mjs:92-102`），
但文案走 async-validator 的默认模板 `'%s is required'`，项目 i18n 没有对应键 →
**中文界面里也冒出英文提示**。

**建议**：给 `el-form` 传 `:rules`，文案走 `t()`。

### P2-9 后端字段级错误无法回显到具体字段

后端 40001 只回一条扁平 msg、不带字段名（`cinema-server/src/main/java/com/cinema/common/exception/GlobalExceptionHandler.java:26-33`），
`err.data` 为空；三个 CRUD 页的 catch 全空 → 用户只知道「保存失败」，
不知道是标题空了、还是影厅名没填、还是票价写成了负数。

**建议**：至少把 msg 落到弹窗顶部的 `el-alert`，让错误留在上下文里（现在 toast 一闪就没了）。

### P2-10 SessionManage 下拉数据加载失败后仍可提交脏数据

`cinema-web/src/views/admin/SessionManage.vue:53-60` catch 为空 → `movies` / `halls` 为空 →
`openCreate` 用 `|| 0` 兜底（`:65-66`）→ 可以提交 `movieId = 0` 的场次。
