## 一句话

**助手现在能真的帮你把票订下来了** —— 对话里说"帮我订明天晚上那场《X》的 2 张连座",它给出带座位号和金额的确认卡,你点一次「确认下单」就锁座建单,聊天里接着出现「待支付卡」,点「去支付」到支付页扫码完成。**付款这一步始终是你自己完成的。**

## 行为变化

| 之前 (v0.1.0) | 现在 (v0.2.0) |
|---|---|
| 助手只输出只读建议卡,点一下跳到选座页 | 助手可以输出**确认卡**,在对话内直接锁座建单 |
| 用户要在座位图上再点一次「确认选座」 | 点一次「确认下单」即可(人工挑座的逃生口仍在) |
| 助手不能锁座 / 支付 / 退票 | 助手**仍然不能自己**锁座/支付/退票 —— 锁座要你点一次确认,付款仍在支付页 |

**没变的**:老的那种「去选座确认」跳转卡**保留**,助手按你的措辞选卡型(说"订/买/下单"→确认卡;说"推荐/看看/有座吗"→跳转卡)。人工挑座永远有路可走。

## 新增功能

### 1. 一键下单确认卡

- 卡片上显示的座位与金额**全部由服务端核验** —— 助手说的座位只是"建议",服务端会重读实时座位图重新挑一组,价格一律取场次表。
- 卡上有 **90 秒倒计时**;过期后按钮置灰,提示重新发起。
- 确认后座位为你锁定 **15 分钟**(订单进入待支付),聊天里追加「待支付卡」。

### 2. 会被取消的旧订单,提前告诉你

如果你在同一场次已经有一笔待支付订单,确认卡上会**显式列出**那笔订单号 —— 因为锁座会取消它。这是从"静默取消"改成"知情取消"。

### 3. 座位被抢了怎么办

确认的瞬间座位被别人抢走,聊天里会明确告诉你「这几个座位刚被抢走了」,并给一个「重新找一组」按钮 —— **不会自动帮你换座重试**(那会跟真实抢票用户踩踏)。

### 4. 回滚开关

```yaml
cinema:
  chat:
    order-enabled: false   # 关掉后助手退回纯只读, 不发版即可生效
```

## 新增接口

| 接口 | 说明 | 门禁 |
|---|---|---|
| `POST /api/chat/orders/proposals` | 重新找一组座位(只传场次与张数) | 登录 + 10 次/分钟 |
| `POST /api/chat/orders/{proposalId}/confirm` | 确认下单(只传 proposalId) | 登录 + 幂等(proposalId,8s)+ 3 次/分钟 |

`/api/chat/message` 仍然公开可匿名,行为不变。

## 技术要点(给维护者)

- **幂等键是 `proposalId`,不是 `userId:sessionId:seatIndexes`** —— 座位列表从不进入幂等键,模型的幻觉/重试产生不了第二把钥匙。
- **提案是服务端快照,存 Redis,TTL 90s,一次性消费**(原子 GETDEL 读出即删)。
- **提案不占位** —— TTL 内座位不保证可用,占位只发生在 `lockSeats` 那一刻。
- **`ChatTools` 没有新增任何 `@Tool`** —— 8 个只读工具与 `ChatToolsStructureTest` 的四条断言一字未改。写路径全在 LLM 之外的后处理装配层。
- **`POST /orders/lock` 与既有抢票链路一行未改** —— 确认端点内部直接复用 `OrderLockService.lockSeats`。
- **`/api/chat/orders/**` 已加入 `AuthRequiredInterceptor` 覆盖路径** —— 未登录返 40101。

详见 `docs/adr/0004-chat-order-proposal.md`。

## 已知限制

1. **依赖 LLM 配合**:助手要输出 `ORDER_PROPOSAL` 卡才会走下单流程。模型不配合时自动退化成 v0.1.0 的只读行为(不影响既有功能)。
2. **提案不占位**:90 秒内座位仍可能被抢,确认时会得到明确提示。
3. **同场次只能有一笔待支付单**(系统既有约束):确认新提案会取消同一场次的旧待支付单 —— 确认卡上会提前告知。
4. **聊天助手需要配置 `DEEPSEEK_API_KEY`** 才能连通 LLM;未配置时 `/api/chat/message` 返 50000,既有下单链路完全不受影响。

## 升级方式

1. 拉代码,数据库**无需变更**(不新增 MySQL 表)。
2. `mvn spring-boot:run` 启动后端、`pnpm dev` 启动前端。
3. 环境变量可选:`CINEMA_CHAT_ORDER_ENABLED`(默认 true)、`CINEMA_CHAT_PROPOSAL_TTL_SECONDS`(默认 90)。
4. 验收建议:对话里说"帮我订明天那场《X》的 2 张连座",确认卡出现 → 点确认 → 待支付卡出现 → 去支付 → 扫码 → 出票。
